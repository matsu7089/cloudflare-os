# Use your ChatGPT plan

Cloudflare OS supports the official **Sign in with ChatGPT** open-source flow. Connect an eligible
ChatGPT account from **AI Providers → Continue with ChatGPT**, then choose one of that account's
models in the chat model selector. Eligible requests use your ChatGPT plan or credits balance.
Open **Manage usage** to review limits and access in [ChatGPT Settings](https://chatgpt.com/settings/usage).

This integration is for personal, self-hosted open-source installations. OpenAI's open-source
authorization flow requires an HTTP loopback callback on the computer running the browser. A Worker
cannot listen on that computer, so the connection screen provides a short-lived helper command.
Commercial or centrally hosted services need to arrange the appropriate integration with OpenAI;
the dynamic open-source registration is not a substitute for that arrangement.

## Connect

1. Configure the backend's `PUBLIC_BASE_URL` to the public HTTPS origin of your installation.
   Local development may use HTTP on `localhost` or `127.0.0.1`. Personal models must be enabled
   by the deployment administrator.
2. Open **AI Providers → Continue with ChatGPT**. Run the displayed command in a checkout of
   cloudflare-os on the computer where you use your browser, with Node.js 24+ and pnpm installed:

   ```sh
   pnpm chatgpt:login --connect '<connection URL copied from AI Providers>'
   ```

3. Complete sign-in and approve ChatGPT plan usage in the browser. Return to AI Providers and
   select **Check connection**. Choose an account-specific model in the composer. No API key,
   client secret, or copied ChatGPT browser cookie is needed.

The helper opens a listener bound only to `127.0.0.1` on an available port. It forwards the OAuth
callback over HTTPS to the installation that created the connection capability. The Worker exchanges
the code with PKCE and verifies the ID token's signature, issuer, audience, expiry, nonce, and
returning-account identity before activating the grant. OAuth access, refresh, and ID tokens stay
in the user's Durable Object; the helper and browser do not receive them.

The command is a single-use capability valid for ten minutes. Keep it private and run only commands
generated by your own installation. Starting another connection invalidates the previous command.
If Cloudflare Access protects your installation, its policy must allow the local helper to POST to
`/api/chatgpt/connect` without an interactive Access session. This narrow endpoint is protected by
the connection capability and does not expose the authenticated Workshop API. An Access login page
or HTTP redirect causes the helper to stop.

## Accounts, renewal, and limits

Each registration has its own stable label, local account ID, issued OAuth client ID, grant, and
model catalog. Reconnect an existing registration to renew consent without creating another client.
The Worker retains a stable agent host ID across sign-ins. **Refresh models** reloads the catalog
for that account; model IDs are the slugs returned by OpenAI, with no hard-coded entitlement list.
An identity-only grant remains visible, but cannot invoke AI until plan permission is granted.

The Worker checks the access token before every HTTP inference request and serializes rotating
refresh-token updates. Invalid renewable grants require reconnecting. Disconnect removes local
credentials and stops existing model references, then attempts OpenAI session revocation. If remote
revocation cannot be confirmed, the UI directs you to disconnect the app in ChatGPT Settings.

ChatGPT requests go directly to `https://api.openai.com/v1/responses`, including on installations
using Cloudflare AI Gateway. They do not consume the deployment's gateway credits or free-tier
model-call allowance. OpenAI enforces the user's shared ChatGPT limits; no API-key fallback occurs
when those limits are reached. Token counts are retained, while API-key dollar prices are not
applied to ChatGPT plan usage.

The transport uses streaming, `store: false`, complete request history, developer instructions, and
namespaced local tools. Unsupported preview parameters are removed. Hosted tools such as image
generation, file search, Code Interpreter, hosted MCP, and tool search are not supported through
this connection. Text, images, and files depend on the selected model's support.
